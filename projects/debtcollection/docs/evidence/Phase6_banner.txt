  THREE THINGS WITH NO PRECEDENT IN THIS REPOSITORY
  --------------------------------------------------------------------------
  * The activity statuscode lifecycle has NO server-side validator. The
    plugin filters qdb_ptpstatus only, and the workspace writes directly
    through Xrm.WebApi with no service layer between — so "server-side"
    means a plugin change, a new step, and an assembly redeploy.
  * Browser WRITES have never executed. create / update / retrieveByKey are
    typed and unit-tested and have never made a real call. Phase 5's three
    runtime defects were all found the first time a path ran for real.
  * Optimistic concurrency has no mechanism. Xrm.WebApi exposes no If-Match,
    so Dataverse ETag concurrency is not reachable through the client API.
    Spike and ADR before any write screen is built on a guess.
