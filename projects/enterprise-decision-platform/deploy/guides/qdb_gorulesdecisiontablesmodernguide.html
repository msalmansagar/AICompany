Choose the hit policy

The hit policy determines what the engine does when more than one row matches.

02

First hit

Default

The engine evaluates rows from top to bottom and returns the first matching row.

  • Place specific rules before general rules.
  • Useful when only one outcome should apply.
  • Returns an empty object when no row matches.

Collect

Multiple

The engine returns every matching row as a collection of results.

  • Apply several fees or promotions.
  • Aggregate scoring criteria.
  • Returns an empty array when no row matches.
💡
Add a default row Leave all input cells empty in the last row so the table can return a meaningful fallback result.

Design inputs and outputs

Input columns contain matching conditions. Output columns contain values or expressions returned by the matching row.

Targeted field mode

Configure a field path once, then write concise unary conditions in each cell.

Field: customer.revenue

>= 100000

Generic expression mode

Use a blank or generic field when each cell must contain a complete expression.

customer.revenue > 100000
and customer.country == "QA"

Authoring best practices

Keep the rule set understandable for both business users and developers.

07
1 Order by specificity For first-hit tables, place narrow conditions before broad rules.
2 Use meaningful labels Readable labels make tables easier to review, test, and maintain.
3 Include a fallback Add a final catch-all row to prevent ambiguous empty outcomes.
4 Keep tables focused Split very large tables into smaller decisions or supporting nodes.
