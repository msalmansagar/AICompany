Basic handler structure

Every function node exports an asynchronous handler that receives the current input and returns a new output object.

02
function-node.js 
/** @type {Handler} */
export const handler = async (input) => {
  // Your business logic here

  return {
    result: "value"
  };
};
Handler exportThe runtime looks for an exported function named handler.
Input parameterContains data from the previous node and upstream node references.
Returned outputThe object becomes the node result passed to downstream nodes.
Async supportThe handler can await HTTP calls, nested decisions, or other asynchronous work.

Access previous node outputs

Use input.$nodes to read fields from any upstream node. Node names are case-sensitive and must match exactly.

03

Read upstream results

Reference node output fields using the exact node name.

const creditScore =
  input.$nodes.CreditCheck.score;

const riskLevel =
  input.$nodes.RiskAssessment.level;

Build a combined decision

Use values from several earlier nodes to calculate the current result.

return {
  approved:
    creditScore > 700 &&
    riskLevel === "low"
};

Example: calculate loyalty points

This function starts with one point per currency unit and applies a multiplier based on the customer tier.

04
loyalty-points.js 
/** @type {Handler} */
export const handler = async (input) => {
  const { orderTotal, customerTier } = input;

  let points = Math.floor(orderTotal);

  const multipliers = {
    platinum: 3,
    gold: 2,
    silver: 1.5,
    bronze: 1
  };

  const multiplier =
    multipliers[customerTier] || 1;

  points = Math.floor(
    points * multiplier
  );

  return {
    loyaltyPoints: points,
    tier: customerTier,
    multiplier
  };
};

Read the inputExtract the order total and customer tier.
2
Calculate base pointsRound the order total down to a whole number.
3
Apply the multiplierUse the configured multiplier for the customer tier.
4
Return a clear resultReturn the final points, tier, and applied multiplier.

Using dayjs

Calculate age and the next birthday from an input date.

import dayjs from 'dayjs';

const today = dayjs();
const birthDate = dayjs(input.birthDate);
const age = today.diff(birthDate, 'year');

Using big.js

Calculate tax and totals without floating-point rounding errors.

import Big from 'big.js';

const price = new Big(input.price);
const tax = price.times(input.taxRate);
const total = price.plus(tax);

Making HTTP requests

Retrieve data from an external API and return the required fields.

import http from 'http';

const response = await http.get(url, {
  params: { currency: input.currency }
});

Use async and await

Function nodes support asynchronous operations, including parallel calls with Promise.all.

06
Receive inputRead the user or record identifiers required for the operation.
Start parallel workCall independent services at the same time with Promise.all.
Aggregate dataCalculate totals or combine the returned information.
Return outputProvide one clean object to the next graph node.
const [userData, orderHistory] = await Promise.all([
  fetchUser(input.userId),
  fetchOrders(input.userId)
]);

return {
  user: userData,
  totalOrders: orderHistory.length,
  lifetimeValue: orderHistory.reduce((sum, order) => sum + order.total, 0)
};

Debug function execution

Use console logging to inspect input data and intermediate calculations. Log output appears in the simulator.

07
export const handler = async (input) => {
  console.log('Input received:', input);

  const result = calculateSomething(input);

  console.log('Calculation result:', result);
  return result;
};
⌁
Log useful checkpoints Log identifiers, input summaries, and important calculation results. Avoid logging confidential values unless required and permitted.

Execution limits

Functions run within the decision engine and must complete within the configured runtime constraints.

08
5,000 msDefault function execution timeout
SharedMemory is shared with the decision engine
⚠
Timeout behavior If the function exceeds the execution timeout, the decision evaluation fails with an error.

Function-node best practices

Keep custom code focused, predictable, and safe to execute inside a decision flow.

09
1Keep functions focusedEach function should perform one clear responsibility.
2Handle errors gracefullyWrap risky work in try/catch and return a structured failure result.
3Avoid side effectsPrefer deterministic functions where the same input produces the same output.
4Use expressions firstPrefer expression nodes when they can handle the logic more simply and efficiently.
export const handler = async (input) => {
  try {
    const result = await riskyOperation(input);
    return { success: true, data: result };
  } catch (error) {
    console.error('Operation failed:', error.message);
    return { success: false, error: error.message };
  }
};
