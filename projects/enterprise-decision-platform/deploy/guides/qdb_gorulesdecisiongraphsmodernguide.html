Processing node types

Each node has a specific responsibility in the decision pipeline.

03
T

Decision Table

Spreadsheet-style rules containing conditions and outcomes.

Use when: several business rules need to be reviewed together.
ƒ

Expression

Transforms, calculates, or reshapes data using expressions.

Use when: values must be calculated or mapped.
JS

Function

Runs custom JavaScript for advanced calculations or integrations.

Use when: logic is too complex for standard expressions.
S

Switch

Routes data to one or more branches according to conditions.

Use when: different inputs require different paths.

Understand connections

Connections show execution direction. One node may receive data from several upstream nodes, and one output may feed several downstream nodes.

05
→ Output to input Connect the right-side output port to the left-side input port.
+ Multiple incoming paths Data from all connected sources is merged before processing.
↗ Multiple outgoing paths The same node output is passed to every connected downstream node.

How data merges

When several nodes feed one node, their output objects are combined into a single input object.

06

Upstream outputs

Discounts: { "discount": 0.15, "reason": "loyalty" } Shipping: { "shipping": 9.99, "method": "standard" }
→

Merged input

{ "discount": 0.15, "reason": "loyalty", "shipping": 9.99, "method": "standard" }
⚠
Field-name conflicts When two sources contain the same field name, the value from a later connection overwrites the earlier value. Use unique names or an outputPath to namespace node results.

Decision evaluation flow

The graph executes in sequence and returns results from the output node or all endpoint nodes.

07
1. Input enters The Input node receives the decision payload.
2. Nodes process Connected tables, expressions, functions, and switches execute.
3. Results move forward Each node passes its result to downstream connections.
4. Output returns The final output or all endpoint results are returned.

Organize complex graphs

Consistent graph structure makes decisions easier to read, review, and maintain.

08
1 Arrange left to right Keep the direction of execution visually consistent across the graph.
2 Group related logic Place rules, calculations, and routing steps that belong together nearby.
3 Use meaningful names Rename nodes so their purpose is clear without opening their configuration.
