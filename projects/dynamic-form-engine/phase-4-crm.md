PERMANENT DESIGN DECISIONS (cannot be changed after table creation)
──────────────────────────────────────────────────────────────────
The following decisions are irreversible in Dataverse once applied.
Any change requires deleting the table, losing all data.

  1. All 12 tables use Organisation-Owned ownership.
     Rationale: form configuration metadata is shared organisation-wide;
     there is no per-user ownership requirement for configuration records.
     Submission and audit tables are also organisation-owned because their
     security is governed by role-level access, not record ownership.

  2. Publisher prefix is qdb_ (seven characters including underscore).
     All logical names and schema names carry this prefix.

  3. Primary key data type is GUID (auto-generated by Dataverse).
     No integer PKs are used anywhere.

  4. qdb_form_submission_log and qdb_form_audit_log are append-only.
     No UPDATE or DELETE is ever issued against these tables.
     This is enforced at the backend service layer and by Dataverse
     security role configuration (no Delete privilege on these tables
     for any user-facing role).

TABLE 1 — qdb_form_definition
══════════════════════════════════════════════════════════════════

Display Name  : Form Definition
Schema Name   : qdb_form_definition
Plural Name   : Form Definitions
Ownership     : OrganizationOwned
Has Notes     : No
Has Activities: No

Purpose
  Root configuration record that defines a single portal form, its
  status lifecycle, draft settings, submission trigger, and access
  control group. One record per unique portal form.

Fields
──────────────────────────────────────────────────────────────────
  qdb_form_definition_id
    Type        : Unique Identifier (Primary Key)
    Required    : System
    Description : Auto-generated GUID. Dataverse primary key.

  qdb_form_code
    Type        : Single Line of Text (maxlength 100)
    Required    : Business Required
    Description : URL-safe unique identifier used in portal URL routing
                  (e.g. 'loan-application', 'kyc-individual'). Must match
                  regex [a-z0-9\-]+. Unique index enforced via Alternate Key.

  qdb_title
    Type        : Single Line of Text (maxlength 250)
    Required    : Business Required
    Description : Human-readable form title displayed in the portal header
                  and admin screens.

  qdb_description
    Type        : Multiple Lines of Text (maxlength 2000)
    Required    : Optional
    Description : Admin-facing description of the form's purpose.

  qdb_status
    Type        : Option Set (local)
    Required    : Business Required
    Options     :
      Draft    = 100000000   (configuring, not visible on portal)
      Active   = 100000001   (live on portal)
      Inactive = 100000002   (hidden, draft resumes blocked)
      Archived = 100000003   (read-only history)
    Default     : Draft (100000000)
    Description : Controls portal visibility. Only Active forms are served
                  by the metadata API. Deactivated forms return HTTP 404.

  qdb_version
    Type        : Whole Number
    Required    : Business Required
    Default     : 1
    Description : Monotonically incrementing integer. Incremented by the
                  backend when a form is published to a new version.

  qdb_allow_save_draft
    Type        : Two Options (Yes/No)
    Required    : Business Required
    Default     : Yes (true)
    Description : When false the portal hides the "Save as Draft" button
                  and does not persist partial submissions.

  qdb_draft_expiry_days
    Type        : Whole Number
    Required    : Optional
    Default     : 90
    Description : Number of days after last modification before a draft
                  is considered expired (BR-004). Configurable per form.

  qdb_power_automate_flow_id
    Type        : Single Line of Text (maxlength 250)
    Required    : Optional
    Description : GUID of the Power Automate cloud flow to trigger via
                  the Dataverse connector on successful submission. The
                  backend calls this flow fire-and-forget (BR-012).

  qdb_confirmation_message
    Type        : Multiple Lines of Text (maxlength 2000)
    Required    : Optional
    Description : Rich-text or plain-text confirmation shown to the user
                  after successful submission. Supports {refNumber}
                  placeholder.

  qdb_confirmation_record_ref_attribute
    Type        : Single Line of Text (maxlength 100)
    Required    : Optional
    Description : Logical name of the Dataverse attribute on the created
                  parent record whose value is shown as the reference
                  number on the confirmation screen (e.g. 'qdb_ref_number').

  qdb_access_group_id
    Type        : Single Line of Text (maxlength 250)
    Required    : Optional
    Description : Azure AD / Entra ID group Object ID. When populated, only
                  members of this group may access the form. When blank, any
                  authenticated user may access it (FR-038).

  Standard Dataverse system fields (present on all tables, not repeated below)
    createdon, modifiedon, createdby, modifiedby, statecode, statuscode

Relationships
──────────────────────────────────────────────────────────────────
  One-to-Many → qdb_form_tab               (via qdb_form_definition_id)
  One-to-Many → qdb_form_business_rule      (via qdb_form_definition_id)
  One-to-Many → qdb_form_submission_mapping (via qdb_form_definition_id)
  One-to-Many → qdb_form_version            (via qdb_form_definition_id)
  One-to-Many → qdb_form_submission_log     (via qdb_form_definition_id)
  One-to-Many → qdb_form_audit_log          (via qdb_form_definition_id)

Alternate Keys / Indexes
──────────────────────────────────────────────────────────────────
  Alternate Key : qdb_form_code (unique constraint enforced by Dataverse)
  Index         : qdb_status (filtered queries by Active status at metadata API)

Business Constraints
──────────────────────────────────────────────────────────────────
  - qdb_form_code must be unique across all records. The alternate key
    enforces this at the platform level.
  - Only records with qdb_status = Active (100000001) and statecode = 0
    are returned by the metadata API endpoint.
  - Version number must only increase — never decrease. The backend
    service enforces this before writing.

TABLE 2 — qdb_form_tab
══════════════════════════════════════════════════════════════════

Display Name  : Form Tab
Schema Name   : qdb_form_tab
Plural Name   : Form Tabs
Ownership     : OrganizationOwned

Purpose
  Represents one navigable tab within a form definition. Multiple
  tabs are rendered as a horizontal tab bar in the portal. Display
  order governs rendering sequence.

Fields
──────────────────────────────────────────────────────────────────
  qdb_form_tab_id
    Type        : Unique Identifier (Primary Key)
    Required    : System

  qdb_form_definition_id
    Type        : Lookup → qdb_form_definition
    Required    : Business Required
    Description : Parent form. Cascade delete — deleting a form definition
                  deletes all its tabs.

  qdb_label
    Type        : Single Line of Text (maxlength 250)
    Required    : Business Required
    Description : Tab label displayed in the portal tab bar (e.g.
                  "Customer Information", "Facility Details").

  qdb_icon_name
    Type        : Single Line of Text (maxlength 100)
    Required    : Optional
    Description : Fluent UI icon name rendered left of the tab label
                  (e.g. "Contact", "Money", "Document"). Ignored if blank.

  qdb_display_order
    Type        : Whole Number
    Required    : Business Required
    Description : Ascending integer controlling tab rendering order.
                  Gaps are allowed to enable reordering without renumbering.

  qdb_is_visible
    Type        : Two Options (Yes/No)
    Required    : Business Required
    Default     : Yes (true)
    Description : Initial visibility state before rule engine fires.
                  A business rule can override this at runtime.

  qdb_requires_previous_tab_complete
    Type        : Two Options (Yes/No)
    Required    : Business Required
    Default     : No (false)
    Description : When true, the user cannot navigate to this tab until
                  all required fields on the previous tab pass validation
                  (FR-007).

Relationships
──────────────────────────────────────────────────────────────────
  Many-to-One → qdb_form_definition (via qdb_form_definition_id, cascade delete)
  One-to-Many → qdb_form_section    (via qdb_form_tab_id, cascade delete)
  Referenced by qdb_form_business_rule (via qdb_target_tab_id)

Indexes
──────────────────────────────────────────────────────────────────
  Composite: (qdb_form_definition_id, qdb_display_order) — used in the
  metadata API order-by query.

Business Constraints
──────────────────────────────────────────────────────────────────
  - display_order values must be unique within a given form definition.
    Enforced at the backend service layer before write.
  - Cascade delete from qdb_form_definition propagates through
    qdb_form_tab → qdb_form_section → qdb_form_field.

TABLE 3 — qdb_form_section
══════════════════════════════════════════════════════════════════

Display Name  : Form Section
Schema Name   : qdb_form_section
Plural Name   : Form Sections
Ownership     : OrganizationOwned

Purpose
  A visual grouping of fields within a tab. Renders as a labelled
  container that can be collapsible. Supports 1-to-4 column grid layouts.

Fields
──────────────────────────────────────────────────────────────────
  qdb_form_section_id
    Type        : Unique Identifier (Primary Key)
    Required    : System

  qdb_form_tab_id
    Type        : Lookup → qdb_form_tab
    Required    : Business Required
    Description : Parent tab. Cascade delete.

  qdb_label
    Type        : Single Line of Text (maxlength 250)
    Required    : Business Required
    Description : Section heading displayed above the field group.

  qdb_description
    Type        : Single Line of Text (maxlength 500)
    Required    : Optional
    Description : Instructional text rendered below the section label.

  qdb_display_order
    Type        : Whole Number
    Required    : Business Required
    Description : Ascending integer controlling section order within the tab.

  qdb_columns
    Type        : Option Set (local)
    Required    : Business Required
    Options     :
      1 Column = 100000001
      2 Columns = 100000002
      3 Columns = 100000003
      4 Columns = 100000004
    Default     : 2 Columns (100000002)
    Description : Number of columns in the section grid. Fields use
                  qdb_column_span to occupy 1–N columns within this grid.

  qdb_is_collapsible
    Type        : Two Options (Yes/No)
    Required    : Business Required
    Default     : No (false)
    Description : When true the section renders with a collapse/expand toggle.

  qdb_is_collapsed_by_default
    Type        : Two Options (Yes/No)
    Required    : Business Required
    Default     : No (false)
    Description : When true and qdb_is_collapsible is true, the section
                  renders collapsed on initial load.

  qdb_is_visible
    Type        : Two Options (Yes/No)
    Required    : Business Required
    Default     : Yes (true)
    Description : Initial visibility state before rule engine fires.

Relationships
──────────────────────────────────────────────────────────────────
  Many-to-One → qdb_form_tab   (via qdb_form_tab_id, cascade delete)
  One-to-Many → qdb_form_field (via qdb_form_section_id, cascade delete)
  Referenced by qdb_form_business_rule (via qdb_target_section_id)

Indexes
──────────────────────────────────────────────────────────────────
  Composite: (qdb_form_tab_id, qdb_display_order)

Business Constraints
──────────────────────────────────────────────────────────────────
  - qdb_is_collapsed_by_default = true is only meaningful when
    qdb_is_collapsible = true. The admin UI should enforce this.
  - display_order must be unique within a given tab.

TABLE 4 — qdb_form_field
══════════════════════════════════════════════════════════════════

Display Name  : Form Field
Schema Name   : qdb_form_field
Plural Name   : Form Fields
Ownership     : OrganizationOwned

Purpose
  Defines one input control within a section. Carries all presentation
  metadata (label, placeholder, tooltip, default), layout (column span,
  display order), behaviour flags (required, readonly, hidden), and
  type-specific configuration (currency code, decimal places, max rows).

Fields
──────────────────────────────────────────────────────────────────
  qdb_form_field_id
    Type        : Unique Identifier (Primary Key)
    Required    : System

  qdb_form_section_id
    Type        : Lookup → qdb_form_section
    Required    : Business Required
    Description : Parent section. Cascade delete.

  qdb_field_type
    Type        : Option Set (local)
    Required    : Business Required
    Options     :
      text          = 100000001
      textarea      = 100000002
      number        = 100000003
      date          = 100000004
      datetime      = 100000005
      dropdown      = 100000006
      multiselect   = 100000007
      lookup        = 100000008
      checkbox      = 100000009
      radio         = 100000010
      currency      = 100000011
      decimal       = 100000012
      email         = 100000013
      phone         = 100000014
      file          = 100000015
      repeatingGrid = 100000016
      richText      = 100000017
    Description : Determines which React component renders this field
                  and which sub-tables are relevant (options, lookup config).

  qdb_schema_name
    Type        : Single Line of Text (maxlength 100)
    Required    : Business Required
    Description : Form-scoped key used as the field name in the submitted
                  JSON payload and in submission mapping lookups. Must be
                  unique within a form definition. Convention: camelCase
                  (e.g. 'customerType', 'facilityAmount').

  qdb_label
    Type        : Single Line of Text (maxlength 250)
    Required    : Business Required
    Description : Field label displayed above or beside the input control.

  qdb_placeholder
    Type        : Single Line of Text (maxlength 250)
    Required    : Optional
    Description : Placeholder text shown inside the input when empty.

  qdb_tooltip
    Type        : Single Line of Text (maxlength 500)
    Required    : Optional
    Description : Help text shown in a tooltip icon next to the field label.

  qdb_default_value
    Type        : Single Line of Text (maxlength 1000)
    Required    : Optional
    Description : Default value pre-populated when the form loads. Stored
                  as a string; the frontend coerces to the field type.

  qdb_display_order
    Type        : Whole Number
    Required    : Business Required
    Description : Ascending integer controlling field order within the section.

  qdb_column_span
    Type        : Option Set (local)
    Required    : Business Required
    Options     :
      1 = 100000001
      2 = 100000002
      3 = 100000003
      4 = 100000004
    Default     : 1 (100000001)
    Description : Number of columns this field occupies within the section
                  grid. Must not exceed qdb_columns on the parent section.

  qdb_is_required
    Type        : Two Options (Yes/No)
    Required    : Business Required
    Default     : No (false)
    Description : Static required flag. The rule engine can override this
                  dynamically (makeRequired / makeOptional actions).

  qdb_is_readonly
    Type        : Two Options (Yes/No)
    Required    : Business Required
    Default     : No (false)
    Description : Static readonly flag. The rule engine can override this.

  qdb_is_hidden
    Type        : Two Options (Yes/No)
    Required    : Business Required
    Default     : No (false)
    Description : Static hidden flag. Hidden fields never render on the
                  portal regardless of business rules.

  qdb_currency_code
    Type        : Single Line of Text (maxlength 10)
    Required    : Optional
    Description : ISO 4217 currency code for currency fields (e.g. 'QAR',
                  'USD'). Ignored for non-currency field types.

  qdb_decimal_places
    Type        : Whole Number
    Required    : Optional
    Description : Number of decimal places for decimal and currency fields.
                  The portal enforces this precision (BR-010).

  qdb_max_rows
    Type        : Whole Number
    Required    : Optional
    Description : Maximum number of rows a user can add in a repeatingGrid
                  field. No limit when null.

  qdb_parent_field_id
    Type        : Lookup → qdb_form_field (self-referential)
    Required    : Optional
    Description : Set on child column fields within a repeatingGrid. Points
                  to the parent repeatingGrid field. Null for top-level fields.

Relationships
──────────────────────────────────────────────────────────────────
  Many-to-One  → qdb_form_section         (via qdb_form_section_id, cascade delete)
  Many-to-One  → qdb_form_field (self)    (via qdb_parent_field_id, no cascade)
  One-to-Many  → qdb_form_field (self)    (child columns of repeatingGrid)
  One-to-Many  → qdb_form_option_value    (via qdb_form_field_id, cascade delete)
  One-to-One   → qdb_form_lookup_config   (via qdb_form_field_id, cascade delete)
  One-to-Many  → qdb_form_validation_rule (via qdb_form_field_id, cascade delete)
  Referenced by qdb_form_business_rule    (via qdb_target_field_id)
  Referenced by qdb_form_submission_mapping (via qdb_form_field_id)

Indexes
──────────────────────────────────────────────────────────────────
  Composite: (qdb_form_section_id, qdb_display_order)
  Single   : qdb_parent_field_id (for child field retrieval)
  Single   : qdb_schema_name (for submission mapping lookups)

Business Constraints
──────────────────────────────────────────────────────────────────
  - qdb_schema_name must be unique within a form definition. Enforced
    at backend service layer (Dataverse does not enforce cross-section
    uniqueness natively).
  - qdb_field_type is permanent once set. Changing a field type requires
    deleting and recreating the field, which also deletes all associated
    validation rules, options, and lookup config.
  - qdb_parent_field_id may only reference a field of type repeatingGrid.
  - qdb_column_span must be less than or equal to the qdb_columns value
    of the parent section. Backend validates before write.

TABLE 5 — qdb_form_validation_rule
══════════════════════════════════════════════════════════════════

Display Name  : Form Validation Rule
Schema Name   : qdb_form_validation_rule
Plural Name   : Form Validation Rules
Ownership     : OrganizationOwned

Purpose
  Defines one validation constraint on a form field. Multiple rules per
  field are evaluated in priority order. The error message is configured
  per rule so each constraint has a precise, user-facing message.

Fields
──────────────────────────────────────────────────────────────────
  qdb_form_validation_rule_id
    Type        : Unique Identifier (Primary Key)
    Required    : System

  qdb_form_field_id
    Type        : Lookup → qdb_form_field
    Required    : Business Required
    Description : The field this rule applies to. Cascade delete.

  qdb_rule_type
    Type        : Option Set (local)
    Required    : Business Required
    Options     :
      required     = 100000001
      minLength    = 100000002
      maxLength    = 100000003
      minValue     = 100000004
      maxValue     = 100000005
      regex        = 100000006
      email        = 100000007
      phone        = 100000008
      dateBefore   = 100000009
      dateAfter    = 100000010
      crossField   = 100000011
    Description : Determines which validation logic the rule engine applies.

  qdb_error_message
    Type        : Single Line of Text (maxlength 500)
    Required    : Business Required
    Description : User-facing error message displayed below the field when
                  this rule fails (FR-020).

  qdb_min_length
    Type        : Whole Number
    Required    : Optional
    Description : Minimum character count. Used when qdb_rule_type = minLength.

  qdb_max_length
    Type        : Whole Number
    Required    : Optional
    Description : Maximum character count. Used when qdb_rule_type = maxLength.

  qdb_min_value
    Type        : Decimal (precision 10, scale 2)
    Required    : Optional
    Description : Minimum numeric value. Used when qdb_rule_type = minValue.

  qdb_max_value
    Type        : Decimal (precision 10, scale 2)
    Required    : Optional
    Description : Maximum numeric value. Used when qdb_rule_type = maxValue.

  qdb_regex_pattern
    Type        : Single Line of Text (maxlength 500)
    Required    : Optional
    Description : ECMAScript-compatible regular expression string. Used when
                  qdb_rule_type = regex. Must not include leading/trailing slashes.

  qdb_compare_to_field_id
    Type        : Lookup → qdb_form_field
    Required    : Optional
    Description : The other field to compare against. Used when
                  qdb_rule_type = crossField.

  qdb_compare_to_value
    Type        : Single Line of Text (maxlength 250)
    Required    : Optional
    Description : Fixed date string (ISO 8601) used when qdb_rule_type is
                  dateBefore or dateAfter with a literal date instead of
                  another field.

  qdb_priority
    Type        : Whole Number
    Required    : Business Required
    Default     : 100
    Description : Rules with lower numbers are evaluated first. When multiple
                  rules fail, the error for the lowest-priority-number rule
                  is shown first.

  qdb_is_active
    Type        : Two Options (Yes/No)
    Required    : Business Required
    Default     : Yes (true)
    Description : Inactive rules are excluded from runtime evaluation.
                  Allows soft-disabling without deletion.

Relationships
──────────────────────────────────────────────────────────────────
  Many-to-One → qdb_form_field (via qdb_form_field_id, cascade delete)
  Many-to-One → qdb_form_field (via qdb_compare_to_field_id, no cascade)

Indexes
──────────────────────────────────────────────────────────────────
  Composite: (qdb_form_field_id, qdb_is_active, qdb_priority)

Business Constraints
──────────────────────────────────────────────────────────────────
  - Exactly one of the type-specific parameter columns (min_length,
    max_length, min_value, max_value, regex_pattern, compare_to_field_id,
    compare_to_value) must be populated, depending on rule_type.
    Backend validates this before write.
  - qdb_compare_to_field_id must reference a field on the same form
    definition as qdb_form_field_id. Backend validates.

TABLE 6 — qdb_form_business_rule
══════════════════════════════════════════════════════════════════

Display Name  : Form Business Rule
Schema Name   : qdb_form_business_rule
Plural Name   : Form Business Rules
Ownership     : OrganizationOwned

Purpose
  Defines one conditional rule evaluated client-side by the rule engine.
  Conditions are stored as JSON. The action targets a field, section, or tab.
  Rules are prioritised so later rules do not overwrite earlier ones
  unintentionally (FR-016).

Fields
──────────────────────────────────────────────────────────────────
  qdb_form_business_rule_id
    Type        : Unique Identifier (Primary Key)
    Required    : System

  qdb_form_definition_id
    Type        : Lookup → qdb_form_definition
    Required    : Business Required
    Description : The form this rule belongs to. Rules are loaded as part of
                  the full form metadata payload.

  qdb_name
    Type        : Single Line of Text (maxlength 250)
    Required    : Business Required
    Description : Human-readable name for admin identification (e.g.
                  "Corporate Customer — Show CR Number Field").

  qdb_description
    Type        : Single Line of Text (maxlength 500)
    Required    : Optional
    Description : Admin-facing explanation of the rule's intent.

  qdb_conditions_json
    Type        : Multiple Lines of Text (no maxlength limit)
    Required    : Business Required
    Description : JSON array of RuleCondition objects. Schema:
                  [{ "fieldId": "...", "operator": "equals",
                     "value": "...", "logicalOperator": "AND" }]
                  Matches the RuleCondition interface in shared/form.types.ts.

  qdb_conditions_logic
    Type        : Option Set (local)
    Required    : Business Required
    Options     :
      AND = 100000000
      OR  = 100000001
    Default     : AND (100000000)
    Description : How the conditions array is combined — all must be true
                  (AND) or at least one must be true (OR).

  qdb_action
    Type        : Option Set (local)
    Required    : Business Required
    Options     :
      showField        = 100000001
      hideField        = 100000002
      showSection      = 100000003
      hideSection      = 100000004
      showTab          = 100000005
      hideTab          = 100000006
      makeRequired     = 100000007
      makeOptional     = 100000008
      makeReadonly     = 100000009
      makeEditable     = 100000010
      setValue         = 100000011
      clearValue       = 100000012
      calculateValue   = 100000013
      filterOptions    = 100000014
      filterLookup     = 100000015
    Description : The action executed when all conditions evaluate to true.

  qdb_target_field_id
    Type        : Lookup → qdb_form_field
    Required    : Optional
    Description : Target field for field-level actions (showField, hideField,
                  makeRequired, setValue, etc.).

  qdb_target_section_id
    Type        : Lookup → qdb_form_section
    Required    : Optional
    Description : Target section for section-level actions (showSection,
                  hideSection).

  qdb_target_tab_id
    Type        : Lookup → qdb_form_tab
    Required    : Optional
    Description : Target tab for tab-level actions (showTab, hideTab).

  qdb_action_value
    Type        : Single Line of Text (maxlength 500)
    Required    : Optional
    Description : The value to set (for setValue), the expression to
                  evaluate (for calculateValue), or the filter expression
                  (for filterOptions / filterLookup).

  qdb_priority
    Type        : Whole Number
    Required    : Business Required
    Default     : 100
    Description : Evaluation order. Lower numbers execute first. Rules with
                  equal priority execute in undefined order.

  qdb_is_active
    Type        : Two Options (Yes/No)
    Required    : Business Required
    Default     : Yes (true)
    Description : Inactive rules are excluded from the metadata API response.

Relationships
──────────────────────────────────────────────────────────────────
  Many-to-One → qdb_form_definition (via qdb_form_definition_id, no cascade)
  Many-to-One → qdb_form_field      (via qdb_target_field_id, no cascade)
  Many-to-One → qdb_form_section    (via qdb_target_section_id, no cascade)
  Many-to-One → qdb_form_tab        (via qdb_target_tab_id, no cascade)

Indexes
──────────────────────────────────────────────────────────────────
  Composite: (qdb_form_definition_id, qdb_is_active, qdb_priority)

Business Constraints
──────────────────────────────────────────────────────────────────
  - Exactly one of qdb_target_field_id, qdb_target_section_id,
